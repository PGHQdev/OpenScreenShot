OpenScreenShot предоставляет локальный MCP-сервер с одним инструментом: `capture_screenshot`. MCP-клиент может вызвать его с URL веб-страницы и получить изображение PNG. Сервер запускает на вашем компьютере отдельный браузер без интерфейса, совместимый с Chrome; расширение для браузера не требуется.

## Добавьте сервер в MCP-клиент

Сначала установите Node.js, pnpm и браузер, совместимый с Chrome. Добавьте запись сервера в формате настроек вашего клиента. Клиенты, которые принимают объект `mcpServers`, могут использовать:

```json
{
  "mcpServers": {
    "openscreenshot": {
      "command": "pnpm",
      "args": ["dlx", "openscreenshot", "serve"]
    }
  }
}
```

Клиент должен находить `pnpm` в своём пути поиска исполняемых файлов. После сохранения настроек перезапустите клиент или перезагрузите его MCP-подключения. Сервер работает через stdio, поэтому клиент запускает локальный процесс; размещённого MCP URL, который нужно ввести, нет.

Если Chrome установлен в необычном месте, передайте `CHROME_PATH` через настройки окружения клиента. Укажите полный путь к исполняемому файлу, а не к папке с приложением.

## Вызов capture_screenshot

Минимальные входные данные инструмента:

```json
{ "url": "https://example.com" }
```

Так получается снимок окна размером 1280 × 800 по умолчанию. Для воспроизводимого запроса задайте размер окна и параметр всей страницы явно:

```json
{
  "url": "https://example.com",
  "fullPage": true,
  "width": 1440,
  "height": 900
}
```

`width` принимает целые числа от 200 до 3840, а `height` — от 200 до 2160. Инструмент возвращает изображение MCP с типом MIME `image/png`. Аргумента для пути вывода у этого инструмента нет. Будет ли результат показан или сохранён, зависит от клиента; если вам сразу нужен файл с именем, используйте [CLI](/ru/blog/screenshot-cli/).

## Что агент видит и чего не видит

Съёмка начинается в новом браузере без интерфейса. Он не наследует cookie или сеанс входа из вашего обычного окна Chrome. Поэтому страница, требующая входа, может дать экран входа. Текущий инструмент не предоставляет шаги входа, подстановку cookie, ожидание селекторов или интерактивные клики.

Прежде чем делать выводы, попросите агента описать, что на самом деле видно на полученном изображении. Скриншот помогает проверить макет, отступы и видимые ошибки; он не может подтвердить, что форма отправляется правильно или что работает навигация с клавиатуры.

## Куда попадает скриншот?

Скриншот создаётся локально и возвращается MCP-клиенту. Если клиент использует размещённую модель, он может передать полученное изображение поставщику модели согласно своим настройкам. Локальная съёмка не означает, что весь разговор с агентом остаётся на устройстве.

Для автоматической съёмки с предсказуемыми размерами см. [скриншоты для CI](/ru/blog/screenshots-for-ci/). [Навык агента для съёмки](/skills/capture-screenshot.md) и [исходный код сервера](https://github.com/pghqdev/OpenScreenShot/blob/main/mcp/src/serve.ts) содержат инструкции для машин и определение инструмента.
